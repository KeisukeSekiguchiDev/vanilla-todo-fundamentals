## 3. 機能要件詳細

### FR-001: ToDoアイテム追加

#### 基本情報

| 項目 | 内容 |
|-----|------|
| 要件ID | FR-001 |
| 機能名 | ToDoアイテム追加 |
| 優先度 | SHALL（必須） |
| 対応UC | UC-001 |
| 対応画面 | SCR-001 |

#### 機能概要

ユーザーがテキスト入力欄にタスク内容を入力し、追加操作を行うと、システムは新しいタスクをリストに追加する。

#### 機能仕様

| 仕様ID | 仕様内容 |
|--------|---------|
| FR-001-01 | システムはテキスト入力欄を1つ提供する |
| FR-001-02 | システムは追加ボタンを1つ提供する |
| FR-001-03 | ユーザーが追加ボタンをクリックすると、システムはタスクを追加する |
| FR-001-04 | ユーザーが入力欄でEnterキーを押下すると、システムはタスクを追加する |
| FR-001-05 | システムは入力値の前後の空白を除去してからタスクを作成する |
| FR-001-06 | システムは空文字または空白のみの入力を受け付けない |
| FR-001-07 | システムは入力値が201文字以上の場合、200文字で切り捨てる |
| FR-001-08 | システムはタスク追加後、入力欄を空にする |
| FR-001-09 | システムはタスク追加後、入力欄にフォーカスを維持する |
| FR-001-10 | システムは一意のID（タイムスタンプベース）を各タスクに付与する |
| FR-001-11 | システムは新規タスクの完了フラグをfalseに設定する |
| FR-001-12 | システムは新規タスクに作成日時を記録する |

#### 受入基準（Gherkin形式）

```gherkin
Feature: ToDoアイテム追加
  ユーザーとして
  新しいタスクをリストに追加したい
  タスクを管理するために

  Background:
    Given ユーザーがToDoアプリを表示している

  @正常系
  Scenario: ボタンクリックでタスクを追加する
    When ユーザーが入力欄に "買い物に行く" と入力する
    And ユーザーが追加ボタンをクリックする
    Then リストに "買い物に行く" が表示される
    And 入力欄が空になる
    And タスクは未完了状態で表示される

  @正常系
  Scenario: Enterキーでタスクを追加する
    When ユーザーが入力欄に "レポートを書く" と入力する
    And ユーザーがEnterキーを押下する
    Then リストに "レポートを書く" が表示される
    And 入力欄が空になる

  @正常系
  Scenario: 前後の空白が除去される
    When ユーザーが入力欄に "  掃除をする  " と入力する
    And ユーザーが追加ボタンをクリックする
    Then リストに "掃除をする" が表示される

  @異常系
  Scenario: 空文字では追加されない
    When ユーザーが入力欄を空のまま追加ボタンをクリックする
    Then リストにタスクは追加されない

  @異常系
  Scenario: 空白のみでは追加されない
    When ユーザーが入力欄に "   " と入力する
    And ユーザーが追加ボタンをクリックする
    Then リストにタスクは追加されない

  @境界値
  Scenario: 200文字のタスクを追加できる
    When ユーザーが入力欄に 200文字のテキストを入力する
    And ユーザーが追加ボタンをクリックする
    Then リストに 200文字のタスクが表示される

  @境界値
  Scenario: 201文字以上は切り捨てられる
    When ユーザーが入力欄に 250文字のテキストを入力する
    And ユーザーが追加ボタンをクリックする
    Then リストに 200文字のタスクが表示される
```

### FR-002: ToDoアイテム削除

#### 基本情報

| 項目 | 内容 |
|-----|------|
| 要件ID | FR-002 |
| 機能名 | ToDoアイテム削除 |
| 優先度 | SHALL（必須） |
| 対応UC | UC-002 |
| 対応画面 | SCR-001 |

#### 機能概要

ユーザーがタスクの削除ボタンをクリックすると、システムは該当タスクをリストから削除する。

#### 機能仕様

| 仕様ID | 仕様内容 |
|--------|---------|
| FR-002-01 | システムは各タスクに削除ボタンを表示する |
| FR-002-02 | ユーザーが削除ボタンをクリックすると、システムは即座に該当タスクを削除する |
| FR-002-03 | システムは削除前に確認ダイアログを表示しない |
| FR-002-04 | システムは削除後にリストを再描画する |
| FR-002-05 | システムは削除後にlocalStorageを更新する |

#### 受入基準（Gherkin形式）

```gherkin
Feature: ToDoアイテム削除
  ユーザーとして
  不要なタスクを削除したい
  リストを整理するために

  Background:
    Given リストに "タスクA" と "タスクB" が存在する

  @正常系
  Scenario: タスクを削除する
    When ユーザーが "タスクA" の削除ボタンをクリックする
    Then "タスクA" がリストから消える
    And "タスクB" はリストに残る

  @正常系
  Scenario: 最後のタスクを削除すると空メッセージが表示される
    Given リストに "タスクC" のみが存在する
    When ユーザーが "タスクC" の削除ボタンをクリックする
    Then "タスクがありません" メッセージが表示される
```

### FR-003: 完了/未完了切り替え

#### 基本情報

| 項目 | 内容 |
|-----|------|
| 要件ID | FR-003 |
| 機能名 | 完了/未完了切り替え |
| 優先度 | SHALL（必須） |
| 対応UC | UC-003, UC-004 |
| 対応画面 | SCR-001 |

#### 機能概要

ユーザーがタスクのチェックボックスをクリックすると、システムはそのタスクの完了状態を反転させる。

#### 機能仕様

| 仕様ID | 仕様内容 |
|--------|---------|
| FR-003-01 | システムは各タスクにチェックボックスを表示する |
| FR-003-02 | 未完了タスクのチェックボックスは未チェック状態で表示される |
| FR-003-03 | 完了タスクのチェックボックスはチェック状態で表示される |
| FR-003-04 | ユーザーがチェックボックスをクリックすると、システムは完了フラグを反転する |
| FR-003-05 | 完了タスクはタスク名に取り消し線を表示する |
| FR-003-06 | 完了タスクはタスク名を薄い色（グレー系）で表示する |
| FR-003-07 | システムは状態変更後にlocalStorageを更新する |

#### 受入基準（Gherkin形式）

```gherkin
Feature: 完了/未完了切り替え
  ユーザーとして
  タスクの完了状態を管理したい
  進捗を把握するために

  @正常系
  Scenario: 未完了タスクを完了にする
    Given リストに未完了の "買い物" が存在する
    When ユーザーが "買い物" のチェックボックスをクリックする
    Then "買い物" が完了状態になる
    And "買い物" に取り消し線が表示される
    And チェックボックスがチェック状態になる

  @正常系
  Scenario: 完了タスクを未完了に戻す
    Given リストに完了の "買い物" が存在する
    When ユーザーが "買い物" のチェックボックスをクリックする
    Then "買い物" が未完了状態になる
    And "買い物" から取り消し線が消える
    And チェックボックスが未チェック状態になる
```

### FR-004: フィルタリング表示

#### 基本情報

| 項目 | 内容 |
|-----|------|
| 要件ID | FR-004 |
| 機能名 | フィルタリング表示 |
| 優先度 | SHALL（必須） |
| 対応UC | UC-005 |
| 対応画面 | SCR-001 |

#### 機能概要

ユーザーがフィルタボタンを選択すると、システムは条件に合致するタスクのみを表示する。

#### 機能仕様

| 仕様ID | 仕様内容 |
|--------|---------|
| FR-004-01 | システムは「すべて」「未完了」「完了」の3つのフィルタボタンを表示する |
| FR-004-02 | システムは初期状態で「すべて」フィルタを選択状態にする |
| FR-004-03 | 選択中のフィルタボタンは視覚的に区別できるスタイルで表示される |
| FR-004-04 | 「すべて」選択時は全タスクを表示する |
| FR-004-05 | 「未完了」選択時は完了フラグがfalseのタスクのみを表示する |
| FR-004-06 | 「完了」選択時は完了フラグがtrueのタスクのみを表示する |
| FR-004-07 | フィルタ変更はlocalStorageのデータを変更しない（表示のみ切替） |
| FR-004-08 | フィルタ条件に合致するタスクが0件の場合、「タスクがありません」を表示する |

#### 受入基準（Gherkin形式）

```gherkin
Feature: フィルタリング表示
  ユーザーとして
  タスクを絞り込んで表示したい
  必要なタスクを素早く確認するために

  Background:
    Given リストに未完了の "タスクA" が存在する
    And リストに完了の "タスクB" が存在する
    And リストに未完了の "タスクC" が存在する

  @正常系
  Scenario: すべてを表示する
    When ユーザーが「すべて」フィルタを選択する
    Then "タスクA" が表示される
    And "タスクB" が表示される
    And "タスクC" が表示される

  @正常系
  Scenario: 未完了のみを表示する
    When ユーザーが「未完了」フィルタを選択する
    Then "タスクA" が表示される
    And "タスクC" が表示される
    And "タスクB" は表示されない

  @正常系
  Scenario: 完了のみを表示する
    When ユーザーが「完了」フィルタを選択する
    Then "タスクB" が表示される
    And "タスクA" は表示されない
    And "タスクC" は表示されない

  @正常系
  Scenario: フィルタ結果が0件の場合
    Given リストに未完了タスクのみが存在する
    When ユーザーが「完了」フィルタを選択する
    Then "タスクがありません" メッセージが表示される
```

### FR-005: データ永続化

#### 基本情報

| 項目 | 内容 |
|-----|------|
| 要件ID | FR-005 |
| 機能名 | データ永続化 |
| 優先度 | SHALL（必須） |
| 対応UC | UC-006 |
| 対応画面 | SCR-001 |

#### 機能概要

システムはタスクデータをブラウザのlocalStorageに自動保存し、ページ再読込時に復元する。

#### 機能仕様

| 仕様ID | 仕様内容 |
|--------|---------|
| FR-005-01 | システムはタスク追加時にlocalStorageへ保存する |
| FR-005-02 | システムはタスク削除時にlocalStorageへ保存する |
| FR-005-03 | システムはタスク状態変更時にlocalStorageへ保存する |
| FR-005-04 | システムはページ読込時にlocalStorageからデータを読み込む |
| FR-005-05 | システムはデータをJSON形式で保存する |
| FR-005-06 | システムは「vanilla-todo-items」キーでデータを保存する |
| FR-005-07 | localStorageにデータが存在しない場合、システムは空のリストで初期化する |
| FR-005-08 | localStorageのデータがJSON形式として不正な場合、システムは空のリストで初期化する |
| FR-005-09 | システムはデータ破損時にlocalStorageの該当キーを削除する |

#### データ形式

```json
[
  {
    "id": "task-1702468800000",
    "text": "買い物に行く",
    "completed": false,
    "createdAt": "2025-12-13T10:00:00.000Z"
  },
  {
    "id": "task-1702468860000",
    "text": "レポートを書く",
    "completed": true,
    "createdAt": "2025-12-13T10:01:00.000Z"
  }
]
```

#### 受入基準（Gherkin形式）

```gherkin
Feature: データ永続化
  ユーザーとして
  タスクデータを保持したい
  ブラウザを閉じても失わないために

  @正常系
  Scenario: タスクがページ再読込後も保持される
    Given ユーザーが "重要な仕事" を追加した
    When ユーザーがページを再読込する
    Then リストに "重要な仕事" が表示される

  @正常系
  Scenario: 完了状態がページ再読込後も保持される
    Given ユーザーが "タスクA" を完了にした
    When ユーザーがページを再読込する
    Then "タスクA" は完了状態で表示される

  @正常系
  Scenario: 削除がページ再読込後も反映される
    Given ユーザーが "タスクB" を削除した
    When ユーザーがページを再読込する
    Then "タスクB" はリストに存在しない

  @異常系
  Scenario: データ破損時は空リストで開始
    Given localStorageに破損したデータが保存されている
    When ユーザーがページを読み込む
    Then リストは空で表示される
    And "タスクがありません" メッセージが表示される
```
