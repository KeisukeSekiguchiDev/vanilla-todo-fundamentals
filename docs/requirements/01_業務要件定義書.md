## 2. 業務概要

### 2.1 業務の目的

本アプリケーションは、ユーザーが日々のタスクを管理するためのToDoリスト機能を提供する。ユーザーはタスクの追加、削除、完了管理を行い、効率的にタスクを処理できる。

### 2.2 対象ユーザー

| ユーザー種別 | 説明 |
|-------------|------|
| 一般ユーザー | ToDoアプリを使用してタスク管理を行う個人 |

---

## 3. 業務フロー

### 3.1 メイン業務フロー

```
[開始]
    |
    v
[ブラウザでアプリにアクセス]
    |
    v
[システムが保存済みデータを読み込む] ------> [保存データなし: 空のリスト表示]
    |
    v
[保存データあり: ToDoリストを表示]
    |
    v
+--[タスク管理ループ]------------------------------------------+
|                                                              |
|   [ユーザーがアクションを選択]                               |
|       |                                                      |
|       +---> [タスク追加] ---> [入力検証] ---> [リスト更新]   |
|       |                                                      |
|       +---> [タスク削除] ---> [確認不要] ---> [リスト更新]   |
|       |                                                      |
|       +---> [完了切替] ---> [状態反転] ---> [リスト更新]     |
|       |                                                      |
|       +---> [フィルタ変更] ---> [表示切替]                   |
|                                                              |
|   [システムがlocalStorageに自動保存]                         |
|                                                              |
+--------------------------------------------------------------+
    |
    v
[ブラウザを閉じる/タブを閉じる]
    |
    v
[終了]
```

## 4. 業務ルール

### 4.1 タスク管理ルール

| ルールID | ルール名 | 内容 |
|---------|---------|------|
| BR-001 | 空タスク禁止 | システムは空文字または空白のみのタスクを追加しない |
| BR-002 | タスク文字数制限 | システムは1タスクあたり最大200文字を許容する |
| BR-003 | 初期状態 | システムは新規タスクを未完了状態で作成する |
| BR-004 | 自動保存 | システムはタスクの追加・削除・状態変更のたびにlocalStorageに自動保存する |
| BR-005 | 削除確認不要 | システムはタスク削除時に確認ダイアログを表示しない（即時削除） |
| BR-006 | 一意識別子 | システムは各タスクに一意のIDを自動付与する |

### 4.2 表示ルール

| ルールID | ルール名 | 内容 |
|---------|---------|------|
| BR-007 | 初期フィルタ | システムはページ読込時に「すべて」フィルタを適用した状態で表示する |
| BR-008 | 完了タスク表示 | システムは完了タスクを取り消し線付きで表示する |
| BR-009 | 空リスト表示 | システムはタスクが0件の場合に「タスクがありません」メッセージを表示する |
| BR-010 | 表示順序 | システムはタスクを追加順（古い順）で表示する |

### 4.3 データルール

| ルールID | ルール名 | 内容 |
|---------|---------|------|
| BR-011 | データ形式 | システムはタスクデータをJSON形式でlocalStorageに保存する |
| BR-012 | ストレージキー | システムは「vanilla-todo-items」キーでデータを保存する |
| BR-013 | データ破損対応 | システムはlocalStorageのデータが破損している場合に空のリストで初期化する |

## 7. ユースケース詳細

### UC-001: タスクを追加する

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-001 |
| ユースケース名 | タスクを追加する |
| アクター | ユーザー |
| 事前条件 | ユーザーがアプリ画面を表示している |
| 事後条件 | 新しいタスクがリストに追加され、localStorageに保存される |

**基本フロー:**

1. ユーザーが入力欄にタスク内容を入力する
2. ユーザーが追加ボタンをクリックする、またはEnterキーを押下する
3. システムが入力値を検証する
4. システムが一意のIDを生成する
5. システムが新しいタスクをリストに追加する
6. システムがlocalStorageにデータを保存する
7. システムが入力欄を空にする
8. システムがリストを再描画する

**代替フロー:**

- 3a. 入力値が空または空白のみの場合:
  - 3a-1. システムはタスクを追加しない
  - 3a-2. システムは入力欄にフォーカスを維持する

### UC-002: タスクを削除する

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-002 |
| ユースケース名 | タスクを削除する |
| アクター | ユーザー |
| 事前条件 | リストに1件以上のタスクが存在する |
| 事後条件 | 指定タスクがリストから削除され、localStorageが更新される |

**基本フロー:**

1. ユーザーが削除対象タスクの削除ボタンをクリックする
2. システムが該当タスクをリストから削除する
3. システムがlocalStorageにデータを保存する
4. システムがリストを再描画する

### UC-003: タスクを完了にする

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-003 |
| ユースケース名 | タスクを完了にする |
| アクター | ユーザー |
| 事前条件 | リストに未完了タスクが存在する |
| 事後条件 | 指定タスクが完了状態になり、localStorageが更新される |

**基本フロー:**

1. ユーザーが未完了タスクのチェックボックスをクリックする
2. システムが該当タスクの完了フラグをtrueに変更する
3. システムがlocalStorageにデータを保存する
4. システムが該当タスクを完了スタイル（取り消し線）で再描画する

### UC-004: タスクを未完了に戻す

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-004 |
| ユースケース名 | タスクを未完了に戻す |
| アクター | ユーザー |
| 事前条件 | リストに完了タスクが存在する |
| 事後条件 | 指定タスクが未完了状態になり、localStorageが更新される |

**基本フロー:**

1. ユーザーが完了タスクのチェックボックスをクリックする
2. システムが該当タスクの完了フラグをfalseに変更する
3. システムがlocalStorageにデータを保存する
4. システムが該当タスクを通常スタイルで再描画する

### UC-005: タスクを絞り込む

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-005 |
| ユースケース名 | タスクを絞り込む |
| アクター | ユーザー |
| 事前条件 | ユーザーがアプリ画面を表示している |
| 事後条件 | 選択したフィルタ条件に合致するタスクのみが表示される |

**基本フロー:**

1. ユーザーがフィルタボタン（すべて/未完了/完了）をクリックする
2. システムが選択されたフィルタをアクティブ状態にする
3. システムがフィルタ条件に合致するタスクのみを表示する

**フィルタ条件:**

| フィルタ | 表示対象 |
|---------|---------|
| すべて | 全タスク |
| 未完了 | 完了フラグがfalseのタスク |
| 完了 | 完了フラグがtrueのタスク |

### UC-006: 保存データを復元する

| 項目 | 内容 |
|-----|------|
| ユースケースID | UC-006 |
| ユースケース名 | 保存データを復元する |
| アクター | システム |
| 事前条件 | ユーザーがアプリ画面にアクセスする |
| 事後条件 | localStorageのデータがリストに反映される |

**基本フロー:**

1. システムがページ読込を検知する
2. システムがlocalStorageから「vanilla-todo-items」キーのデータを取得する
3. システムがJSONデータをパースする
4. システムがタスクリストを描画する

**代替フロー:**

- 2a. データが存在しない場合:
  - 2a-1. システムは空のリストを初期化する
- 3a. JSONパースに失敗した場合:
  - 3a-1. システムは空のリストを初期化する
  - 3a-2. システムは破損データを削除する
